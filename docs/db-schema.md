# Database Schema Reference — TimeGuard (Supabase / PostgreSQL 15)

> Source of truth: `supabase/migrations/001_initial_schema.sql`
> Keep this doc in sync with the migration files whenever either changes.

## Tenant Isolation Rule

Every table except `tenants` and `platform_settings` carries a
`tenant_id uuid NOT NULL` column.  Supabase Row-Level Security (RLS) is
enabled on every such table.  The Rust API additionally injects `tenant_id`
from the validated JWT claim — never from a request body.

## Tables

### `tenants`
Platform-global.  One row per company/customer.

| Column | Type | Notes |
|---|---|---|
| id | uuid PK | gen_random_uuid() |
| name | text NOT NULL | display name |
| slug | text UNIQUE NOT NULL | URL-safe identifier |
| plan | tenant_plan NOT NULL | DEFAULT 'TRIAL' |
| status | tenant_status NOT NULL | DEFAULT 'TRIAL' |
| screenshot_interval_sec | int | DEFAULT 300 (5 min) |
| retention_days | int | DEFAULT 30 |
| storage_quota_mb | int | DEFAULT 5000 |
| max_teams | int | DEFAULT 5 |
| max_seats | int | DEFAULT 10 |
| created_at | timestamptz | DEFAULT now() |
| updated_at | timestamptz | DEFAULT now() |

---

### `users`
Linked to Supabase Auth via `auth.users(id)`.  SUPER_ADMIN has `tenant_id = NULL`.

| Column | Type | Notes |
|---|---|---|
| id | uuid PK | REFERENCES auth.users(id) ON DELETE CASCADE |
| tenant_id | uuid | REFERENCES tenants(id); NULL for SUPER_ADMIN |
| role | user_role NOT NULL | |
| tracking_mode | tracking_mode | DEFAULT 'VISIBLE' |
| full_name | text | |
| email | text UNIQUE NOT NULL | |
| avatar_url | text | |
| consent_at | timestamptz | employee consent timestamp; required before tracking |
| device_token_hash | text | bcrypt hash of UUID issued to desktop agent |
| is_active | bool | DEFAULT true |
| created_at | timestamptz | DEFAULT now() |

### `teams` / `team_members`

**teams**: `id, tenant_id, name, description, created_at`

**team_members**: `(team_id, user_id)` composite PK, plus `tenant_id` for RLS.

---

### `attendance_sessions`

One row per clock-in → clock-out cycle.

| Column | Type |
|---|---|
| id | uuid PK |
| tenant_id | uuid |
| user_id | uuid |
| clocked_in_at | timestamptz |
| clocked_out_at | timestamptz nullable |
| total_break_sec | int DEFAULT 0 |
| status | text (OPEN \| CLOSED) |

### `break_periods`

`id, session_id (FK attendance_sessions), tenant_id, user_id, started_at, ended_at`

---

### `activity_events`

One row per "user was in app/site from t0 to t1".  Produced by agent poll.
Classified at write-time via `ProductivityRule` lookup.

`id, tenant_id, user_id, app_name, window_title, domain (nullable),
 started_at, ended_at, classification, created_at`

### `idle_periods`

`id, tenant_id, user_id, started_at, ended_at`

---

### `screenshots`

`id, tenant_id, user_id, storage_path (Supabase Storage key), taken_at,
 is_blurred (bool), created_at`

### `timelapse_jobs`

`id, tenant_id, user_id, date (date), status (PENDING|PROCESSING|DONE|FAILED),
 video_path (nullable), created_at`

---

### `productivity_rules`

Tenant-defined rules matching app names or domains to a classification.

`id, tenant_id, match_type (APP|DOMAIN), pattern (text), classification,
 priority (int, higher wins), created_at`

### `alert_rules`

Thresholds that cause the alerts engine cron to generate `alerts`.

`id, tenant_id, type, threshold_sec (for IDLE_TOO_LONG), threshold_pct
 (for LOW_PRODUCTIVITY), is_active`

### `alerts`

Generated by the cron engine.

`id, tenant_id, user_id, type, severity, payload (jsonb), is_read (bool),
 triggered_at`

---

### `audit_logs`

Platform-global.  Logs super-admin impersonation and sensitive actions.

`id, actor_id, target_user_id, action (text), metadata (jsonb), created_at`

### `platform_settings`

Key-value store for global platform config.

`key (text PK), value (jsonb), updated_at`

---

## Indexes (recommended)

```sql
CREATE INDEX ON activity_events (tenant_id, user_id, started_at DESC);
CREATE INDEX ON screenshots      (tenant_id, user_id, taken_at DESC);
CREATE INDEX ON alerts           (tenant_id, is_read, triggered_at DESC);
CREATE INDEX ON attendance_sessions (tenant_id, user_id, clocked_in_at DESC);
```

## RLS Policies (see migration 002)

- `tenants`: only SUPER_ADMIN can SELECT/UPDATE.
- All other tables: TENANT_ADMIN can SELECT/INSERT/UPDATE/DELETE where
  `tenant_id = (SELECT tenant_id FROM users WHERE id = auth.uid())`.
- EMPLOYEE can SELECT only own rows (`user_id = auth.uid()`).
- `audit_logs`, `platform_settings`: SUPER_ADMIN only.
